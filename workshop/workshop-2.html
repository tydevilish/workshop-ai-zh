สูตรคิด prompt ที่ใช้ได้ตลอดชีวิต

นี่คือบทเรียนจริงของวันนี้ prompt ทั้ง 3 ตัวข้างล่างเกิดจากสูตรเดียวกันนี้หมด ครูเอาไปใช้สั่งงานอย่างอื่นได้เลย ไม่จำกัดแค่เกมคำศัพท์

ต้องบอก AI ถ้าไม่บอก จะเจออะไร
1. ผลลัพธ์ที่จับต้องได้
"ไฟล์ HTML ไฟล์เดียว ดับเบิลคลิกเปิดได้"		 AI ให้โปรเจกต์ที่ต้องลงโปรแกรมเพิ่มก่อนถึงจะเปิดได้ ครูเปิดไม่ได้เลย
2. ข้อห้าม
"ห้ามใช้ของจากอินเทอร์เน็ต"		 AI เลือกวิธีที่ตัวเองถนัด ซึ่งมักพังบนเครื่องครู
3. ข้อมูลจริง ไม่ใช่คำบรรยาย
วางคำศัพท์ 38 คำลงไปตรง ๆ · ให้รหัสสีเป็นตัวเลข		 บอกว่า "ใส่คำศัพท์พื้นฐาน" AI จะแต่งคำเอง บอกว่า "สีสดใส" ได้หน้าตาคนละแบบทุกครั้ง
4. ให้ทำอะไรตอนพัง
"ห้ามหน้าจอขาว ให้ขึ้นข้อความไทยบอกแทน"		 พังแล้วขาวเปล่า ครูแก้เองไม่ได้ จบเลย
5. รูปแบบคำตอบ
"ส่งไฟล์เดียวจบ ห้ามแบ่ง 2 ข้อความ"		 ได้โค้ดครึ่งเดียว ต้องเอา 2 ท่อนมาต่อกันเอง ซึ่งคนไม่เขียนโค้ดทำไม่ได้
ลำดับสำคัญ: บอกข้อห้ามก่อนบอกสิ่งที่อยากได้เสมอ AI อ่านทั้งข้อความก็จริง แต่สิ่งที่บอกก่อนมีน้ำหนักกว่า และถ้าไม่กันไว้ตั้งแต่แรก มันจะเลือกวิธีที่มันคุ้นเคยไปแล้วก่อนจะถึงเงื่อนไขของเรา

คำที่จะได้ยินบ่อยวันนี้

  • Prompt (พร้อมต์): ข้อความที่เราพิมพ์สั่ง AI ยิ่งบอกละเอียด ยิ่งได้ตรงใจ วันนี้เราไม่พิมพ์เอง กดปุ่มคัดลอกจากหน้านี้ไปวาง
  • ไฟล์ HTML: ไฟล์หน้าเว็บ 1 ไฟล์ ดับเบิลคลิกแล้วเปิดในเบราว์เซอร์ได้เลย เหมือนเปิดไฟล์ Word
  • Canvas: หน้าต่างที่ Gemini เปิดขึ้นมาข้าง ๆ เวลาเขียนโค้ดยาว ในนั้นมีปุ่มดูตัวอย่าง (Preview) และปุ่มดาวน์โหลด
  • แชท: หน้าคุยกับ AI 1 หน้า วันนี้ต้องอยู่แชทเดียวตลอด เพราะ AI จำงานเดิมได้เฉพาะในแชทเดียวกัน
  • เกมจำความคืบหน้าไว้ในเบราว์เซอร์: เปิดใหม่แล้วคะแนนยังอยู่ แต่ถ้าล้างประวัติเบราว์เซอร์จะหาย

บอกผู้เรียนก่อนเริ่ม

  1. เปิด gemini.google.com ล็อกอินด้วยบัญชี Google ให้พร้อม
  2. กดปุ่ม คัดลอก Prompt 1 ในหน้านี้ → กลับไปที่ Gemini → คลิกช่องพิมพ์ข้อความล่างสุด → กด Ctrl+V (Windows) หรือ Cmd+V (Mac) → กด Enter
  3. รอจน Gemini พิมพ์โค้ดเสร็จ อย่าเพิ่งพิมพ์อะไรแทรก
  4. ดูผลงานได้เลยโดยยังไม่ต้องเซฟไฟล์: ถ้า Gemini เปิด Canvas ให้กดแท็บ Preview ในนั้น จะเห็นเกมทำงานทันที ถ้าไม่มี Canvas ให้ข้ามไปทำขั้นเซฟไฟล์ (Step 3) ก่อนแล้วค่อยเปิดดู
  5. Prompt 2 ต้องวางในแชทเดิม ห้ามเปิดแชทใหม่ ถ้าเปิดใหม่ AI จะลืมเกมที่เพิ่งทำ
  6. ผลของแต่ละคนจะไม่เหมือนกัน เป็นเรื่องปกติ

Step 1: หน้าแรก + โหมดจับคู่คำศัพท์

ที่มาของ Prompt 1: จากประโยคเดียว กลายเป็นข้อความยาวได้ยังไง

ถ้าครูนึกอยากได้เกมนี้เอง สิ่งที่ครูจะพิมพ์จริงคือประโยคสั้น ๆ ประมาณนี้:

"ช่วยทำเว็บเกมจับคู่คำศัพท์ภาษาจีนให้หน่อย มีเสียงอ่านด้วย"

ประโยคนี้ไม่ผิด และ AI ตอบได้ แต่ตอบแบบเดาใจเราหมดทุกช่อง Prompt 1 คือประโยคนี้บวกคำตอบของคำถามที่ AI ต้องเดา ทีละข้อ:

AI ต้องเดาอะไร ถ้าปล่อยให้เดา เลยเติมอะไรลงไป
เอาไปเปิดยังไง ให้โปรเจกต์ที่ต้องลงโปรแกรมก่อน ครูเปิดไม่ได้ "ไฟล์ HTML ไฟล์เดียว ดับเบิลคลิกเปิด ไม่ต้องลงอะไร"
ใช้คำศัพท์อะไร AI แต่งคำเอง ไม่ตรงกับที่ครูสอน วางคำศัพท์ 38 คำของอาจารย์ลงไปในตัว prompt เลย
ภาษาบนหน้าจอ ปุ่มและข้อความเป็นอังกฤษ "ข้อความทุกอย่างเป็นภาษาไทย คำศัพท์คงเป็นจีน"
หน้าตาเป็นยังไง ได้คนละแบบทุกครั้งที่สั่ง ให้รหัสสีจริงเป็นตัวเลข ไม่ใช่คำว่า "สดใส"
เสียงอ่านมาจากไหน AI เลือกบริการที่ต้องสมัครและใส่รหัส ให้โค้ดฟังก์ชันเสียงที่ทดสอบแล้วไปเลย ไม่ต้องให้คิดเอง
พังแล้วทำไง หน้าจอขาวเปล่า "ห้ามหน้าจอขาว ให้ขึ้นข้อความไทยบอกแทน"

พูดอีกแบบ: prompt ยาวไม่ได้เก่งกว่า prompt สั้นเพราะความยาว แต่เพราะมันปิดช่องที่ AI ต้องเดาไปทีละช่อง ทุกช่องที่ปล่อยไว้คือจุดที่ผลลัพธ์ของ 200 คนจะแตกกัน

Prompt 1

Build me a Chinese vocabulary game as ONE self-contained HTML file.
I am a Chinese language teacher. I cannot write or read code.

## OUTPUT REQUIREMENT
A single .html file containing all HTML, CSS and JavaScript.
I will double-click it to open it in a browser. No server, no install, no build step.

## HARD RULES — breaking any of these makes the game fail completely
- No external libraries. No <script src="https://...">. No React, Vue, Tailwind CDN, jQuery.
  Plain vanilla JavaScript only.
- Do NOT use <script type="module">, and do NOT use import or export.
  The file runs from file:// where ES modules are blocked and nothing would execute.
- Do NOT use fetch() or XMLHttpRequest on local files. It always fails with
  "TypeError: Failed to fetch" on file://.
- All vocabulary data is embedded below. Do not load any code, library, font or
  data from the network. The ONLY network request allowed in the whole app is the
  pronunciation audio URL given further down.
- All UI text (titles, buttons, messages, labels) must be in THAI.
  The vocabulary itself stays Chinese, shown with its pinyin. Code and comments are English.

## HOME SCREEN
The app opens on a home screen with a title and two large buttons:
  1. "จับคู่คำศัพท์"  -> matching mode (build this now)
  2. "ผสมคำ"          -> combine mode (show the button, but it opens a screen
                          that just says "เร็ว ๆ นี้" for now)
Every screen has a way back to the home screen.

## MATCHING MODE (build this fully)
- One round shows 5 Chinese words on the left and their 5 Thai meanings on the right,
  shuffled. The player taps a Chinese word then taps a Thai meaning.
- Correct pair: both lock in green with a short animation, and the pinyin is revealed.
- Wrong pair: both flash red briefly and unselect. Never block the player, never show a
  dead end.
- When all 5 pairs are matched, show a result card with the score and a
  "รอบต่อไป" button that starts a new round with 5 different words.
- Track how many of the 38 words the player has matched correctly at least once,
  and show it as "จำได้แล้ว 12/38" on the home screen.
- Save that progress in localStorage so it survives closing the browser.
- Every Chinese word has a speaker button that plays its pronunciation using this
  exact function (it is already tested and works from file://):

function speak(hanzi) {
  const url = 'https://translate.google.com/translate_tts?ie=UTF-8'
    + '&q=' + encodeURIComponent(hanzi)
    + '&tl=zh-CN&total=1&idx=0'
    + '&textlen=' + hanzi.length
    + '&client=tw-ob&prev=input&ttsspeed=1';
  new Audio(url).play().catch(() => {
    const u = new SpeechSynthesisUtterance(hanzi);
    u.lang = 'zh-CN';
    speechSynthesis.speak(u);
  });
}

Use new Audio() directly. Never fetch() that URL.

## HOW COMBINE MODE WORKS
Every word in the data splits into two single characters, for example 父母 = 父 + 母.
The player's job is to find which two characters form a real word.

- The player first picks a category: ครอบครัว, ธรรมชาติ, ทิศทาง, กริยาคู่ตรงข้าม,
  คุณศัพท์คู่ตรงข้าม, นามธรรม.
  Only that category's characters appear on screen — never all of them at once.
  This keeps each round small enough to actually solve.
- The single characters from that category appear as cards, shuffled.
  A character card shows ONLY the character itself. Do NOT display a meaning or a
  pinyin for a single character: I did not give you those, and inventing them would
  teach my students something wrong. Meanings appear only after a correct pair.
- The player drags one character onto another, or taps two characters in a row on phone.
- If those two characters form a word in the data, in either order, it counts as found:
  play a short reveal animation and show a result card with the compound word,
  its pinyin, its Thai meaning, and a speaker button.
  Show an HSK badge when the word has one:
  HSK1 东西 | HSK2 左右 | HSK3 买卖 | HSK3 风雨 | HSK4 往返 | HSK4 出入
  HSK5 是非 | HSK5 成败 | HSK5 得失 | HSK5 生死
  Show the same badge in matching mode too.
- If they do not form a word, show a small Thai message and separate the cards again.
  Never freeze, never throw an error.
- Cards must never overlap. When placing a card or when a drop does not form a word,
  compute the nearest free position once and place it there. That is all.
  Do NOT write a physics engine and do NOT run an animation loop that keeps pushing
  cards apart — it makes cards jitter and become impossible to drag.
- Show progress for the category, for example "พบแล้ว 3/4" , and overall "พบแล้ว 12/38".
- Found words are saved in localStorage together with the matching-mode progress.
